# Dexmate 采集性能检查与优化

## 结论与范围

RTX 4080 SUPER，Isaac Sim 5.1.0。实际查询确认物理设备为 CPU／NumPy，触觉为 CUDA，RGB 为 RTX。
基线为一轮完整抓取；最终配置连续两轮完整抓取均通过。每轮仍为 18 秒、2160 个物理步、
各模态 540 条 30 Hz 保存记录，保留五路原分辨率视频。

| 测量区间 | 旧配置 | 最终配置 |
| --- | ---: | ---: |
| 环境 step 总耗时／轮 | 201.95 s | 61.68 s（两轮平均） |
| 相机采样／轮，已包含在 step 中 | 103.51 s | 3.31 s |
| 同步额外 render 刷新次数 | 2164／轮，包含 reset | 0，两轮均无额外刷新 |
| 正常运动阶段渲染次数／轮 | 2160 | 540 |
| 数值／源视频 append 耗时／轮 | 0.89 s | 0.85 s |
| 数值落盘及视频结束检查／轮 | 0.93 s | 0.80 s |
| 首条组合预览＋GIF | 12.06 s | 11.87 s |

核心采集 step **约加速 3.27 倍**。旧配置一轮各顶层计时合计 243.94 s；
最终配置两轮合计 169.79 s，应用日志到退出为 170.891 s（均不包括外部 Conda 启动开销）。
两轮共享一次启动、一次约 13.24 s 的轨迹求解，且仅首轮生成预览，不能把总耗时直接当作
不同摆放条件下每轮都能达到的固定耗时。新姿态仍需求解 IK。

计时是调用的墙钟时间，包含 GPU 等待。`capture`、`render_flush`、`world_step` 等有嵌套，
不能与 `env_step` 相加。触觉调用从约 9.82 s／轮降到约 1.42 s／轮，但触觉算法未改，
这也反映了减少 GPU 渲染排队的影响，并非声称 Warp 内核本身加速。

## 改动

1. 采集时关闭三路未保存的 1200×900 摆放检查视角；单独场景验证器仍默认创建它们。
2. `render_mode=camera`：每四个物理步调用一次带渲染的 `world.step`，中间三步只推进物理。
3. 启用同步完成渲染的 `waitIdle=1`、`checkForHydraRenderComplete=1000`。
   配置来自已安装的 5.1.0 `isaacsim.exp.base.zero_delay.kit`，也见
   [NVIDIA 5.1 官方说明](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/python_scripting/util_snippets.html#rendering-frame-delay)。
4. 在已有时间对齐检查之外，要求每台相机原始 `ReferenceTime` 严格前进；共用离线读取器也检查。
5. 同一进程里，物体变化参数和初始关节状态字节完全相同时复用已求解动作；第二轮命中缓存一次。
6. 增加各阶段计时、实际设备、渲染刷新计数；`--no-preview` 可将组合预览延后离线生成。

默认采用优化配置；旧流程可用 `--render-mode physics --diagnostic-cameras --no-zero-delay` 对照。
未改变物理参数、相机分辨率、控制频率、触觉公式和抓取验收阈值。

## 正确性验证

- 最终两轮全部抓取、碰撞、reset、时钟和视频计数检查通过。
- 每轮全部 2160 个物理步，包括不渲染的中间步，与旧十轮采集的首轮基线比较：
  关节位置／速度、物体位置／朝向、夹爪矩阵、完整触觉数组的最大绝对差均为 **0**。
- 抬升范围 50.087–50.116 mm，最大滑移 0.0488 mm；两轮一致。
- 图像实际映射时间误差为 0；原始渲染引用逐帧前进，没有时钟插值警告。
- 共用读取器两轮均可读取：`[8,10)` 各模态 60 行，四路 RGB 解码为 480×640×3。
- 查看最终夹持预览，RGB 为抬升抓取画面，热图在下方；观察视频首帧与保持帧的平均像素变化
  分别为 7.7966／7.7958，排除静止画面重复编码。
- 仿真侧 19 项测试通过；Dex Wire 全量 323 passed、5 skipped；相应 Ruff 通过。

### 被排除的试验

`dexmate_perf_optimized_20260916_v1` 是无效试验：只推进物理后，旧渲染引用被映射为当前时间，
导致时钟检查通过但 RGB 停留在 reset。该目录已添加 `INVALID_RECORDING.md`，不作为训练数据
或性能结论；新离线读取器会直接拒绝它。原始报告保留作诊断证据。

中间 v2 试验每次采样显式 `world.render()`，两轮物理和画面均正确，但出现时钟插值回退警告。
最终 v3 使用每四步一次正常带渲染步进，消除了这些警告。
